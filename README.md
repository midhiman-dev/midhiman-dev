## How I Approach Architecture

**Start with the business problem, not the AI**  
Understand the workflow, users, systems, rules, and constraints first. Add AI only where it actually helps.

**Keep facts and rules in code where possible**  
Calculations, validations, permissions, and important business rules should not depend on an AI model guessing correctly.

**Keep people in control of important decisions**  
Approvals, sensitive actions, and high-impact decisions should remain reviewable by a person.

**Design for the systems that already exist**  
Most enterprise work involves existing applications, APIs, databases, security rules, and legacy code. I design with those realities in mind.

**Test before adding more features**  
A smaller solution that works and can be explained is more valuable than a large feature list that has not been properly tested.

## Selected Projects

### [CarbonCoach](https://github.com/midhiman-dev/CarbonCoach)
**AI-assisted carbon tracking with rule-based calculations**

- Carbon calculations are done in code rather than by the AI model
- AI is used for explanation, coaching, and everyday suggestions
- A custom check rejects unsupported numbers generated by the model
- Privacy checks reduce unnecessary personal data sent to the AI service
- **286 automated tests** with approximately **94.79% statement coverage**

**What it shows:** use AI for the parts it is good at, while keeping important facts and calculations under normal software control.

### [VoteReady India](https://github.com/midhiman-dev/VoteReady-India)
**AI-powered civic information using trusted sources**

- Answers are based on a controlled set of trusted sources
- Official sources are preferred where available
- The application can say it cannot verify something instead of inventing an answer
- Some types of questions are handled by normal application rules rather than being sent directly to AI
- **164-test regression suite**

**What it shows:** an AI application should be able to explain where its information comes from and should not pretend to know what it cannot verify.

### [NFI CMDWS](https://github.com/midhiman-dev/NFI_CMDWS)
**Role-based beneficiary management workflow**

A public prototype/reference implementation for managing beneficiary cases through structured roles, documents, reviews, approvals, and status changes.

It demonstrates:

- Role-based workflows
- Document handling
- Human review and approval stages
- Case status tracking
- Audit and traceability needs

**What it shows:** good enterprise architecture is often about making workflows, responsibilities, and decisions clearer before adding new technology.

### [AI Engineering Utilities](https://github.com/midhiman-dev/Utilities)
**Small tools that support AI development and integration**

Includes:

- **SecureLLMHarness** — a .NET 8 command-line tool for testing OpenAI-compatible AI endpoints, checking responses, measuring latency, and troubleshooting integrations without exposing API keys
- **Redact Secrets** — a local utility for finding and masking passwords, API keys, tokens, private keys, and other sensitive values before logs or files are shared

**What it shows:** building AI systems also requires practical tools for testing, troubleshooting, and protecting sensitive information.

### [TripLedger-Nano](https://github.com/midhiman-dev/TripLedger-Nano)

A smaller non-AI project that demonstrates end-to-end product delivery using Firebase, Google sign-in, budget forecasting, category tracking, and PDF reporting.

**What it shows:** I also build complete applications where normal software design and business rules are the main focus.
